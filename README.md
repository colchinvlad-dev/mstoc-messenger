## О проекте

**MTSoC Messenger** — коммерческий корпоративный мессенджер, разработанный для организации защищённого общения внутри школ и образовательных учреждений. Продукт готов к продаже и внедрению: единая платформа для учителей, учеников, администрации и техподдержки.

**Роль:** Full-stack разработчик (единственный разработчик проекта)
**Статус:** готов к коммерческому использованию
**Год:** 2025–2026

### Ключевые задачи, которые решает мессенджер

- **Единая коммуникация** — все участники образовательного процесса в одном защищённом пространстве
- **Разграничение доступа** — двухуровневая ролевая модель (системная роль + роль внутри чата)
- **Конфиденциальность** — шифрование сообщений индивидуальным ключом для каждого чата
- **Самостоятельная регистрация** — школы регистрируют учителей и учеников через пригласительные коды
- **Аудит безопасности** — логирование всех событий с фиксацией IP и User-Agent

## Возможности

### Аутентификация и безопасность

- **Регистрация и вход** с хешированием паролей через **bcrypt**
- **Токены сессий** с ограниченным сроком действия (7 дней)
- **Двухуровневая ролевая модель (RBAC):**
  - Системная роль: `super_admin`, `admin`, `teacher`, `student`, `support`
  - Роль внутри чата: `owner`, `admin`, `member`
- **Шифрование сообщений** — индивидуальный ключ для каждого чата
- **Логирование событий безопасности:**
  - Вход и выход из системы
  - Ошибки аутентификации
  - Смена пароля
  - Фиксация IP и User-Agent
- **Диагностический скрипт** для проверки корректности хеширования паролей

### Чаты и сообщения

- **Личные и групповые чаты**
- **Системные чаты**, автоматически создаваемые для каждого пользователя:
  - «Избранное» — личные заметки
  - «Техподдержка» — обращения к support
  - «Администрация» — связь с руководством
- **Разделение видимости** — в системных чатах пользователь видит только свои обращения
- **AJAX-обновление** интерфейса без перезагрузки страницы
- **Отправка файлов и изображений** с валидацией, ресайзом и защитой от вредоносных файлов

### Пригласительные коды

- Привязка к конкретной школе, классу и типу пользователя
- Ограничение количества использований
- Ограничение по сроку действия
- Возможность регистрации без участия администратора

### Управление

- **Панель администратора** для управления пользователями, чатами, школами
- **Модерация** сообщений и пользователей
- **Просмотр логов** безопасности
- **Статистика** по активности

## Архитектура базы данных

**Общее количество таблиц:** 18+

**Ключевые таблицы:**

| Таблица | Назначение |
|---------|------------|
| `users` | Пользователи с ролями и хешами паролей |
| `schools` | Школы и образовательные учреждения |
| `classes` | Классы (привязка к школе) |
| `chats` | Чаты (личные, групповые, системные) |
| `chat_members` | Участники чатов с ролями |
| `messages` | Сообщения с шифрованием |
| `message_attachments` | Вложенные файлы и изображения |
| `invite_codes` | Пригласительные коды |
| `sessions` | Токены активных сессий |
| `security_logs` | Логи событий безопасности |
| `chat_keys` | Ключи шифрования для каждого чата |

### Особенности БД

- **Транзакции ACID** — для критических операций (регистрация, создание чата, отправка сообщения)
- **Каскадные удаления** — при удалении чата удаляются все сообщения и участники
- **Индексы** — для ускорения поиска по чатам, сообщениям, пользователям
- **Логирование** — все действия с фиксацией IP и User-Agent

## Установка и запуск

### Требования

**Минимальные:**

- **PHP 8.5** или выше с расширениями: `pdo_mysql`, `openssl`, `mbstring`, `gd`
- **MySQL 8.4** или выше
- **Nginx** или **Apache**
- **Docker** и **Docker Compose** (для контейнерного запуска)

### Вариант 1. Запуск через Docker (рекомендуется)

**1. Клонировать репозиторий**

```bash
git clone https://github.com/colchinvlad-dev/mtsoc-messenger.git
cd mtsoc-messenger
```

**2. Скопировать переменные окружения**

```bash
cp .env.example .env
```

**3. Настроить `.env`**

```env
APP_ENV=production
APP_URL=http://localhost:8080

DB_HOST=db
DB_PORT=3306
DB_NAME=mtsoc
DB_USER=mtsoc_user
DB_PASS=secure_password

ENCRYPTION_KEY=your_random_32_char_key_here
SESSION_LIFETIME=604800
```

**4. Запустить контейнеры**

```bash
docker compose up -d --build
```

**5. Импортировать схему БД**

```bash
docker compose exec db mysql -u mtsoc_user -p mtsoc < database/schema.sql
```

**6. Открыть в браузере**

```
http://localhost:8080
```

### Вариант 2. Локальный запуск без Docker

**1. Установить зависимости**

```bash
composer install
npm install
npm run build
```

**2. Настроить `.env`**

Укажи параметры подключения к локальному MySQL.

**3. Импортировать БД**

```bash
mysql -u root -p < database/schema.sql
```

**4. Запустить через встроенный сервер PHP**

```bash
php -S localhost:8000 -t public/
```

**5. Открыть**

```
http://localhost:8000
```

## Как пользоваться

### 1. Создание школы (super_admin)

После первого запуска создай супер-администратора через seed или SQL:

```sql
INSERT INTO users (email, password_hash, system_role, name)
VALUES (
    'admin@mtsoc.local',
    '$2y$10$...', -- хеш пароля через password_hash('admin123', PASSWORD_BCRYPT)
    'super_admin',
    'Главный администратор'
);
```

### 2. Регистрация администратора школы

Супер-админ создаёт учётную запись школы и генерирует invite-код для администратора.

### 3. Приглашение учителей и учеников

Администратор школы генерирует пригласительные коды с параметрами:

- Класс (для учеников)
- Тип пользователя (`teacher` / `student` / `support`)
- Срок действия
- Максимальное число использований

### 4. Регистрация по коду

Пользователь переходит по ссылке `register.php?code=XXXXX` и завершает регистрацию.

### 5. Общение

- Личные и групповые чаты
- Системные чаты: «Избранное», «Техподдержка», «Администрация»
- Отправка файлов и изображений
- Все сообщения шифруются

## Безопасность

### Аутентификация

- **bcrypt** для хеширования паролей (cost 10+)
- **Сессионные токены** в БД с ограниченным сроком жизни (7 дней)
- **Принудительный выход** при смене пароля
- **Логирование** всех событий входа/выхода

### Авторизация

- **RBAC** — двухуровневая модель:
  - Системная роль (доступ к разделам админ-панели)
  - Роль в чате (права на управление участниками)
- Проверка прав **на сервере** для каждого защищённого запроса
- Middleware `AuthMiddleware` и `RoleMiddleware`

### Шифрование

- **Индивидуальный ключ** для каждого чата
- Ключи хранятся в таблице `chat_keys` в зашифрованном виде
- Шифрование сообщений через **OpenSSL** (AES-256)
- Ключ расшифровывается только для участников чата

### Защита данных

- **SQL-инъекции** — подготовленные выражения PDO
- **XSS** — экранирование вывода через `htmlspecialchars()`
- **CSRF** — токены для форм, изменяющих состояние
- **Загрузка файлов** — валидация MIME-типа, ресайз изображений, блокировка исполняемых файлов
- **Rate limiting** — ограничение частоты попыток входа

### Аудит

Таблица `security_logs` фиксирует:

- Вход и выход
- Ошибки аутентификации
- Смену пароля
- Изменение ролей
- Создание и удаление чатов
- Отправку файлов

С полями `ip_address`, `user_agent`, `created_at`.
